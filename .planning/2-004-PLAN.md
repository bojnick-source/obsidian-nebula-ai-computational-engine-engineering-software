## Objective

Populate the planned-but-empty fixture directories listed in
`forge-tests/FIXTURE_INDEX.md`. These YAML fixtures are consumed by pytest
as test data and are required for the acceptance test suite to be complete.

## Acceptance Criteria

1. `forge-tests/fixtures/phase_1_2/` contains at least one YAML file
   covering vault write + read-back (memory intake).
2. `forge-tests/fixtures/phase_1_3/` contains at least one YAML file
   covering gap detection (missing knowledge detection).
3. `forge-tests/fixtures/golden/verifier_red_team/` contains expected-verdict
   YAML files corresponding to the existing red-team inputs:
   - `provenance_errors_golden.yaml` — expected verdicts for `provenance_errors.yaml`
   - `unit_errors_golden.yaml` — expected verdicts for `unit_errors.yaml`
4. All new YAML files pass `yamllint .` (run from repo root).
5. `forge-tests/FIXTURE_INDEX.md` is updated with rows for all new fixtures.
6. Each fixture follows the schema:
   ```yaml
   description: "..."
   tags: [component, scenario]
   milestone: "v0.1 | Lane X"
   input:
     # ... problem input
   expected:
     # ... expected output / verdict
   ```

## Known Risk

- **P5 — YAML truthy `on:`**: Not applicable here (not a GitHub Actions file).
- **P6 — YAML line-too-long**: Keep all YAML lines under 120 chars. Use `|`
  block scalars for multi-line strings instead of long inline strings.
- Fixture YAML files must use 2-space indentation for list items (`  - item`),
  not 4-space. This is enforced by yamllint via `.yamllint.yml`.
