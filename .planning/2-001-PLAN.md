## Objective

Implement `forge_agent/core/pipeline.py` — a Python pipeline runner that
executes the 9-phase FORGE core loop end-to-end, tying together all
existing components: ModelRouter, MechanicalEngineer specialist, GMSH/CalculiX
MCP wrappers, run_all_gates(), ObsidianVaultManager, and AgentJournal.

The C++ orchestrator in `forge-core/` is scaffolded but its phase 2–8
implementations are stubs. This Python runner is the MVP integration layer
that satisfies v0.1 acceptance criteria AC-01 through AC-10.

## Acceptance Criteria

1. `PipelineRunner(config).run(task_request)` returns a `TaskResult` dataclass.
2. The same `trace_id` UUID appears in: blackboard dict, specialist output,
   tool invocation envelopes, JSONL log events, vault note frontmatter.
3. Each of the 9 phases emits a JSONL start-event and end-event with keys:
   `trace_id`, `phase`, `status` ("ok"|"degraded"|"error"), `duration_ms`.
4. If `run_all_gates(specialist_output)` returns any gate with `passed=False`,
   the pipeline blocks vault write and sets `TaskResult.status = "failed"`.
5. After a successful vault write, `ObsidianVaultManager.amnesia_check(path)`
   is called; if it returns `False`, the JSONL log records
   `ERR_VAULT_AMNESIA` and `TaskResult.unresolved_gaps` is non-empty.
6. `PipelineRunner` accepts a `tool_executor` parameter (default: real MCP
   subprocess calls) so unit tests can inject mock tool executors.
7. `pytest forge_agent/tests/test_pipeline_runner.py -q` passes with 0 errors.

## Implementation Steps

1. Create `forge_agent/core/pipeline.py`:
   - `@dataclass TaskRequest` (task_type, project, component, description, load_cases)
   - `@dataclass TaskResult` (trace_id, status, result_summary, confidence,
     artifact_refs, unresolved_gaps, what_would_falsify)
   - `class PipelineRunner` with `__init__(self, config: dict, tool_executor=None,
     vault_manager=None, anthropic_client=None)`
   - `run(request: TaskRequest) → TaskResult`
   - `_run_phase_intake`, `_run_phase_routing`, `_run_phase_decomposition`,
     `_run_phase_memory_preflight`, `_run_phase_specialist`,
     `_run_phase_tool_execution`, `_run_phase_verification`,
     `_run_phase_persistence`, `_assemble_output`
   - `_emit_jsonl(phase, status, duration_ms, **extra)` — writes to logger

2. Trace ID: generate once in `_run_phase_intake` via `str(uuid.uuid4())`.
   Attach to all outgoing envelopes and vault frontmatter.

3. Phase 5 (specialist): call `anthropic_client.messages.create()` with
   `MechanicalEngineer.SYSTEM_PROMPT`. If `anthropic_client` is None, use a
   stub that returns a pre-built valid contract-compliant dict (enables
   offline tests).

4. Phase 6 (tool_execution): call `tool_executor.run_gmsh(...)` then
   `tool_executor.run_calculix(...)`. Both accept trace_id and task_id.
   Default `DefaultToolExecutor` calls the real MCP servers via subprocess
   (guarded by `shutil.which` checks — degrades gracefully if binary absent).

5. Phase 7 (verification): call `run_all_gates(specialist_output_dict)`.
   If any gate fails, set blackboard `"verification.status" = "failed"` and
   do NOT proceed to phase 8. Log each gate result.

6. Phase 8 (persistence): build vault frontmatter from blackboard
   (trace_id, domain, component, project, type="finding").
   Call `vault_manager.upsert_note(path, markdown, frontmatter)`. (Note: second param is named `markdown`, NOT `content` — using `content=` as a keyword arg raises `TypeError`.)
   Then call `vault_manager.amnesia_check(path)`.

7. Create `forge_agent/tests/test_pipeline_runner.py`:
   - `test_trace_id_propagated_through_all_phases` — mock tool executor,
     mock anthropic client; verify same trace_id in result, JSONL events,
     vault note path
   - `test_verification_failure_blocks_vault_write` — inject invalid
     specialist output (missing equations); verify vault_manager.upsert_note
     NOT called
   - `test_pipeline_returns_complete_on_happy_path` — full mock run;
     result.status == "complete"
   - `test_jsonl_has_9_phase_start_and_end_events` — capture JSONL output;
     assert 9 start + 9 end events, all contain trace_id

## Known Risk

- **P1 — Method name mismatch**: Verify every method name called on
  `ObsidianVaultManager` (upsert_note, amnesia_check, search_notes) actually
  exists on the class before committing. Read obsidian_manager.py line-by-line.
- **P2 — Accepted-but-unused parameters**: `tool_executor` and
  `anthropic_client` must both have at least one code path that uses them.
  Do not accept them silently.
- **P3 — HALF_OPEN circuit breaker**: Not applicable here (no circuit breaker
  in pipeline). DefaultToolExecutor retries use the existing CalculiX server's
  4-attempt policy — do not re-implement retry logic here.
