## Objective

Implement two complementary verification capabilities in a new module
`forge_agent/core/adversarial_verifier.py`:

1. **AdversarialVerifier** — LLM-backed agent that attempts to falsify specialist
   output by listing the top-3 challenges/failure modes. Returns structured result
   with `challenges`, `unresolved_count`, and a `verdict` of `"challenged"` or
   `"unchallenged"`. Issues `WARN_ADVERSARIAL_CHALLENGE` when unresolved challenges
   remain.

2. **ConfidenceCalibrator** — deterministic (no LLM) calibrator that adjusts a
   specialist's claimed confidence downward based on gate failures and unresolved
   adversarial challenges. Issues `WARN_CONFIDENCE_MISMATCH` when claimed confidence
   exceeds calibrated by ≥ 0.15.

Both are standalone classes; neither requires the Phase 6-001 gates to exist first
(they consume the existing `GateResult` type already defined in verifier.py).

## Acceptance criteria

1. `AdversarialVerifier(client).challenge(specialist_output, blackboard)` returns an
   `AdversarialResult` with `challenges: list[str]` (length 1–3), `unresolved_count: int`,
   `verdict: str`.
2. When `unresolved_count > 0`, `AdversarialResult.warn_code` equals
   `"WARN_ADVERSARIAL_CHALLENGE"`.
3. When `unresolved_count == 0`, `verdict == "unchallenged"` and `warn_code` is `None`.
4. `AdversarialVerifier` works with a mocked Anthropic client (no live API in tests).
5. `ConfidenceCalibrator.calibrate(claimed, gate_results, adversarial_result)` returns
   a float in `[0.0, 1.0]`.
6. If all gates pass and `adversarial_result.unresolved_count == 0`, calibrated equals
   `claimed` (no penalty).
7. Each failed gate reduces confidence by 0.05; each unresolved challenge reduces by
   0.05; result clamped to `[0.0, 1.0]`.
8. `ConfidenceCalibrator.calibrate()` returns `(calibrated, warn_code)` where
   `warn_code == "WARN_CONFIDENCE_MISMATCH"` iff `claimed - calibrated >= 0.15`, else
   `warn_code` is `None`.
9. pytest: ≥ 8 new tests in `forge_agent/tests/test_adversarial_verifier.py`;
   full suite passes (≥ 486 + 8 = 494 tests, stacking on 6-001).

## Implementation steps

1. **Create `forge_agent/core/adversarial_verifier.py`**:

   ```python
   from __future__ import annotations
   from dataclasses import dataclass, field
   from typing import Any

   ADVERSARIAL_SYSTEM_PROMPT = """\
   You are a ruthless engineering critic. Your job is to find fatal flaws.
   Given a specialist's analysis, list exactly 3 potential failure modes or
   falsifying conditions — things that, if true, would invalidate the analysis.
   Return JSON:
   {
     "challenges": ["<challenge 1>", "<challenge 2>", "<challenge 3>"],
     "unresolved_count": <int 0-3>,
     "verdict": "challenged" | "unchallenged"
   }
   Set unresolved_count to the number of challenges that would still block
   acceptance. Set verdict to "challenged" if unresolved_count > 0.
   """
   ```

   `AdversarialResult` dataclass: `challenges: list[str]`, `unresolved_count: int`,
   `verdict: str`, `warn_code: str | None`.

   `AdversarialVerifier.challenge(specialist_output: str, blackboard: dict) → AdversarialResult`:
   - Call LLM with ADVERSARIAL_SYSTEM_PROMPT.
   - Parse JSON response using `_try_parse_json` (copy helper or import from verifier).
   - Set `warn_code = "WARN_ADVERSARIAL_CHALLENGE"` iff `unresolved_count > 0`.

2. **Add ConfidenceCalibrator class** in same file:
   - `calibrate(claimed: float, gate_results: list[GateResult], adversarial_result: AdversarialResult | None = None) → tuple[float, str | None]`
   - `penalty = 0.05 * failed_gate_count + 0.05 * (adversarial_result.unresolved_count if adversarial_result else 0)`
   - `calibrated = max(0.0, min(1.0, claimed - penalty))`
   - `warn_code = "WARN_CONFIDENCE_MISMATCH" if (claimed - calibrated) >= 0.15 else None`
   - All three parameters (`claimed`, `gate_results`, `adversarial_result`) must be
     read; never silently ignored (P2 guard).

3. **Import GateResult** from `forge_agent.core.verifier` (already exists).

4. **Write tests** in `forge_agent/tests/test_adversarial_verifier.py`:
   - Mock Anthropic client returning valid JSON with 0, 1, 3 challenges.
   - ConfidenceCalibrator: no penalty (all pass, 0 challenges); gate penalty;
     adversarial penalty; combined > 0.15 → WARN_CONFIDENCE_MISMATCH;
     result clamp to 0.0.

## Known risks

- **P1 (interface mismatch)**: `AdversarialVerifier.challenge()` calls
  `client.messages.create()` — verify the mock in tests matches the real Anthropic
  async API shape (or use sync for consistency with existing tests in the suite).
  Check existing test mocks in `test_pipeline_runner.py` for the pattern to follow.
- **P2 (ignored param)**: `adversarial_result` in `calibrate()` defaults to `None`
  but must be read to extract `unresolved_count`; the `None` branch is explicitly
  tested.
- **P7 (error codes)**: Use `WARN_ADVERSARIAL_CHALLENGE` and `WARN_CONFIDENCE_MISMATCH`
  exactly as spelled in `docs/contracts/error-codes.md`.
