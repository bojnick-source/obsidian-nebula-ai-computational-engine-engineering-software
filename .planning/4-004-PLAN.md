## Objective

Add OpenFOAM and SU2 CFD solver support to FORGE by:

1. Creating MCP wrapper servers `forge_agent/mcp_wrappers/openfoam_server.py` and
   `forge_agent/mcp_wrappers/su2_server.py` following the exact same pattern as
   `gmsh_server.py` and `calculix_server.py`.
2. Registering `@_register("openfoam_run")` and `@_register("su2_run")` handlers in
   `forge_agent/core/cli_dispatcher.py`.
3. Adding `run_openfoam()` and `run_su2()` methods to `DefaultToolExecutor` in
   `forge_agent/core/pipeline.py` following the same pattern as `run_calculix()`.

Both wrappers return a `status="degraded"` envelope when the solver binary is absent
(`foamRun` / `SU2_CFD` not on PATH), consistent with the existing GMSH/CalculiX pattern.

## Acceptance Criteria

1. `pytest forge_agent/tests/test_openfoam_su2_wrappers.py -v` exits 0.
2. Both server modules return a response with `$schema == "forge/mcp/response/v1"`.
3. When `foamRun` is absent from PATH, `openfoam_server` returns `status="degraded"` and
   `error_code="ERR_TOOL_SUBPROCESS_FAIL"`.
4. When `SU2_CFD` is absent from PATH, `su2_server` returns `status="degraded"` and
   `error_code="ERR_TOOL_SUBPROCESS_FAIL"`.
5. Both envelopes include `task_id` in `metadata` when provided.
6. `DefaultToolExecutor.run_openfoam()` and `run_su2()` return `status="degraded"` when
   binaries are absent, following the same pattern as `run_calculix()`.
7. `cli_dispatcher` has registered handlers for `"openfoam_run"` and `"su2_run"`.
8. When binaries are absent, `CliDispatcher.call("openfoam_run", {...})` returns
   `(None, False)` (raises `CliToolError` → handled=False, MCP fallback triggered).

Pytest command: `pytest forge_agent/tests/test_openfoam_su2_wrappers.py -v`

## Design

### `openfoam_server.py` structure

File: `forge_agent/mcp_wrappers/openfoam_server.py`

```python
TOOL_ID = "openfoam"
WRAPPER_VERSION = "1.0.0"

_FOAM_BIN: str | None = shutil.which("foamRun") or shutil.which("simpleFoam")

def create_server() -> FastMCP:
    app = FastMCP(
        name="openfoam-wrapper",
        instructions="OpenFOAM CFD solver wrapper. ...",
    )

    @app.tool()
    def run_openfoam(
        trace_id: str,
        task_id: str,
        invocation_id: str,
        case_dir: str,
        solver: str = "simpleFoam",
        timeout_ms: int = 300000,
    ) -> dict:
        """Run an OpenFOAM CFD case.

        Args:
            trace_id:      Task trace ID
            task_id:       Task identifier
            invocation_id: Unique per-invocation ID
            case_dir:      Absolute path to the OpenFOAM case directory
            solver:        Solver name (default: simpleFoam)
            timeout_ms:    Timeout in milliseconds (default: 300000)

        Returns:
            MCP Wrapper Envelope v1 with output.{log_file, residuals, converged}
        """
        t0 = time.perf_counter()

        bin_path = shutil.which(solver) or _FOAM_BIN
        if bin_path is None:
            return error_envelope(
                TOOL_ID, WRAPPER_VERSION, trace_id, invocation_id,
                "ERR_TOOL_SUBPROCESS_FAIL",
                f"OpenFOAM binary '{solver}' (or foamRun) not found on PATH — "
                "install OpenFOAM or add to PATH",
                (time.perf_counter() - t0) * 1000,
                status="degraded",
            )
        # ... subprocess run, log parse, success_envelope
```

Note: the `task_id` parameter is included in every tool signature (matching
`gmsh_server.py`) and must be referenced — it is stored in the metadata.

### `task_id` in metadata (P1 guard)

The `gmsh_server.py` tool signature accepts `task_id` but the `_envelope.py`
`success_envelope()` and `error_envelope()` signatures do NOT include `task_id`
as a positional parameter — it is NOT forwarded to envelope functions.
Confirmed from `_envelope.py` lines 24-52 and 55-79.

The `task_id` is therefore referenced inside the tool handler body (e.g., logged
or included in the output dict) to satisfy P2. AC5 tests that `task_id` appears
in the `metadata` field — implementation puts it in `metadata` via a wrapper
around the standard envelope helpers.

Solution: add `task_id` to the returned dict after calling `success_envelope()` /
`error_envelope()`:

```python
result = error_envelope(...)
result["metadata"]["task_id"] = task_id
return result
```

This satisfies P2 (parameter is used) and AC5 (task_id in metadata).

### `cli_dispatcher.py` handlers

```python
@_register("openfoam_run")
async def _openfoam_run(args: dict) -> dict:
    case_dir = args.get("case_dir", "")
    solver = args.get("solver", "simpleFoam")
    if not shutil.which(solver) and not shutil.which("foamRun"):
        raise CliToolError(
            f"OpenFOAM binary '{solver}' not found on PATH"
        )
    # subprocess call ...

@_register("su2_run")
async def _su2_run(args: dict) -> dict:
    config_file = args.get("config_file", "")
    if not shutil.which("SU2_CFD"):
        raise CliToolError("SU2_CFD not found on PATH")
    # subprocess call ...
```

### `DefaultToolExecutor` additions

```python
def run_openfoam(
    self,
    trace_id: str,
    task_id: str,
    invocation_id: str,
    **kwargs: Any,
) -> dict:
    if shutil.which("foamRun") is None and shutil.which("simpleFoam") is None:
        return {
            "tool": "openfoam",
            "trace_id": trace_id,
            "task_id": task_id,
            "invocation_id": invocation_id,
            "status": "degraded",
            "reason": "OpenFOAM binary (foamRun/simpleFoam) not found on PATH",
        }
    return {"tool": "openfoam", "trace_id": trace_id, "task_id": task_id,
            "invocation_id": invocation_id, "status": "ok"}

def run_su2(
    self,
    trace_id: str,
    task_id: str,
    invocation_id: str,
    **kwargs: Any,
) -> dict:
    if shutil.which("SU2_CFD") is None:
        return {
            "tool": "su2",
            "trace_id": trace_id,
            "task_id": task_id,
            "invocation_id": invocation_id,
            "status": "degraded",
            "reason": "SU2_CFD binary not found on PATH",
        }
    return {"tool": "su2", "trace_id": trace_id, "task_id": task_id,
            "invocation_id": invocation_id, "status": "ok"}
```

   call signatures (completed above).

   pattern, retry delays, binary detection (`shutil.which`), log parsing approach
   (completed above).

   a. Binary detection: `shutil.which("foamRun") or shutil.which("simpleFoam")`.
   b. `run_openfoam` tool: degraded if no binary; else `subprocess.run` in ThreadPoolExecutor.
   c. Log parse: scan `log.simpleFoam` for final residual and convergence.

## Known Risks

- OpenFOAM exposes multiple solver binaries (`simpleFoam`, `pimpleFoam`, `rhoSimpleFoam`,
  `foamRun` in v11+). The wrapper detects `foamRun` first (v11+) then falls back to
  `simpleFoam`. The `solver` parameter allows overriding at call time. The degraded
  condition checks both.
- SU2 history CSV column names changed between SU2 v7 and v8. The Phase 4 implementation
  reads `cl` and `cd` with case-insensitive column lookup; a parsing failure returns
  `ERR_TOOL_OUTPUT_INVALID`.
- The `task_id` is accepted in all three existing wrappers (gmsh, calculix) but is not
  forwarded to the envelope helpers — it is used in log messages and returned in metadata.
  This plan follows the same convention rather than changing the `_envelope.py` API.
