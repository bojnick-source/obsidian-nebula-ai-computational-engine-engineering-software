## Objective

Create Python agent modules for the `mujoco_sim` domain of the Void Vanguard project:

1. `forge_agent/agents/vanguard/mujoco_simulation.py` — ROLE, MODEL, TEMPERATURE,
   SYSTEM_PROMPT constants for the MuJoCo Simulation Specialist.

2. `forge_agent/agents/vanguard/mujoco_simulation_antagonist.py` —
   `MuJoCoSimulationAntagonist(AntagonistAgent)` with heuristic `_generate_critique()`
   that validates determinism and trajectory quality.

3. `forge_agent/tests/test_vanguard_mujoco.py` — all acceptance criteria as tests.

The specialist interfaces with the existing `mujoco_step` CLI handler
(`cli_dispatcher.py` lines 608-698) which outputs:
`steps, sim_time_s, seed, mjcf_sha256, joint_pos, joint_vel, contact_forces,
trajectory_file, provenance`.

## Acceptance Criteria

1. `pytest forge_agent/tests/test_vanguard_mujoco.py -v` exits 0.
2. `MuJoCoSimulationAntagonist` is a subclass of `AntagonistAgent`.
3. `MuJoCoSimulationAntagonist().critique(output, context)` returns a valid dict when called
   with an empty specialist output (default info critique path).
4. When `specialist_output` is missing the `"seed"` key, critique returns `severity="fatal"`.
5. When `specialist_output["steps"] < 100`, critique returns `severity="warning"`.
6. When `specialist_output` has `seed=42` and `steps=500`, critique returns `severity="info"`.
7. `mujoco_simulation.SYSTEM_PROMPT` is a non-empty string containing "MuJoCo" or "MJCF".
8. `mujoco_simulation.ROLE == "mujoco_simulation_specialist"`.
9. Both `specialist_output` and `context` reach `_generate_critique` (P2 guard).

### `forge_agent/agents/vanguard/mujoco_simulation_antagonist.py`

```python
class MuJoCoSimulationAntagonist(AntagonistAgent):
    def __init__(self) -> None:
        super().__init__(
            agent_id="mujoco_simulation_antagonist",
            domain="mujoco_sim",
        )

    def _generate_critique(
        self,
        specialist_output: dict,
        context: dict,
    ) -> dict:
        _ = context  # consumed (P2)

        # AC 4: missing seed → non-deterministic → fatal
        if "seed" not in specialist_output:
            return {
                "error_code": None,
                "critique_type": "methodology",
                "severity": "fatal",
                "detail": (
                    "No random seed was specified in the simulation output. "
                    "Without a fixed seed, the MuJoCo simulation trajectory is "
                    "non-deterministic and cannot be reproduced for verification, "
                    "CMA-ES fitness evaluation, or sim-to-real gap measurement. "
                    "Every FORGE simulation must record the seed used."
                ),
                "evidence": (
                    "MuJoCo Simulation SKILL.md: deterministic step validation "
                    "requires fixed seed (MVP requirement). mujoco_step CLI "
                    "handler always returns seed in output."
                ),
                "confidence_delta": -0.6,
            }

        # AC 5: steps < 100 → insufficient duration → warning
        steps = specialist_output.get("steps")
        if steps is not None:
            try:
                steps_val = int(steps)
            except (TypeError, ValueError):
                steps_val = None
            if steps_val is not None and steps_val < 100:
                return {
                    "error_code": None,
                    "critique_type": "methodology",
                    "severity": "warning",
                    "detail": (
                        f"Simulation ran only {steps_val} steps, below the 100-step "
                        "minimum required for trajectory quality assessment. Short "
                        "trajectories do not cover sufficient state space for "
                        "CMA-ES fitness evaluation or contact force characterisation."
                    ),
                    "evidence": (
                        "MuJoCo Simulation SKILL.md: trajectory must be ≥ 100 steps "
                        "minimum (MVP gate)."
                    ),
                    "confidence_delta": -0.2,
                }

        # Default: info on sim-to-real gap
        return {
            "error_code": None,
            "critique_type": "methodology",
            "severity": "info",
            "detail": (
                "Simulation trajectory meets basic determinism and duration requirements. "
                "Sim-to-real gap has not been quantified in this output. Domain "
                "randomisation (DR) perturbation ranges are not verified here. "
                "Contact model parameters (solimp/solref) should be validated against "
                "measured PAM contact behaviour before handoff to CMA-ES."
            ),
            "evidence": (
                "MuJoCo Simulation SKILL.md: sim-to-real gap quantification is "
                "a Level 3 (V1) capability. DR configuration required for CMA-ES input."
            ),
            "confidence_delta": -0.05,
        }
```

## Known Risks

- The `mujoco_step` CLI handler requires the `mujoco` Python package at import time.
  The specialist module (constants only) has no runtime dependency on mujoco.
  The antagonist module is purely heuristic — no mujoco import needed.
- `steps` is returned as an integer by the CLI handler. The antagonist defensively
  wraps the int() conversion to handle float or string values from future mock data.
