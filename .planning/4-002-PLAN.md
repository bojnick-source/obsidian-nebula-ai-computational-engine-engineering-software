## Objective

Create `forge_agent/core/debate_orchestrator.py` — a self-contained `DebateOrchestrator`
that drives one or more rounds of specialist→antagonist critique→response within
`forge_agent/`. Then integrate it into `pipeline.py` as Phase 5b (inserted between
Phase 5 specialist output and Phase 6 tool execution). When an antagonist is configured
and debate produces `maintained_disagreement` with a `fatal` critique, the assembled
`TaskResult` carries `status="disputed"` and a `debate_verdict` field.

The `forge-learning/debate_lifecycle.py` is used as design reference only.
No cross-package import from `forge-learning` is permitted — it is a separate
installable package with its own dependency chain (direct `anthropic.Anthropic`
constructor, sync API) that could break if forge-learning is not installed.

## Acceptance Criteria

1. `pytest forge_agent/tests/test_debate_orchestrator.py -v` exits 0.
2. Mock specialist + mock antagonist returning `severity="info"` → `DebateResult.verdict == "consensus"`.
3. Mock antagonist returning `severity="fatal"` → `DebateResult.verdict == "maintained_disagreement"`.
4. Pipeline with an injected `DebateOrchestrator` (antagonist configured) runs and `TaskResult` includes `debate_verdict` field.
5. Pipeline with no antagonist configured skips debate entirely; `TaskResult.debate_verdict` is `None`.
6. `DebateResult.rounds` is always an integer ≥ 1.
7. `DebateResult.critiques` is a list (may be empty).
8. `debate_verdict="maintained_disagreement"` + `fatal` severity → `TaskResult.status == "disputed"`.

Each AC has a corresponding test in `forge_agent/tests/test_debate_orchestrator.py`.
Pytest command: `pytest forge_agent/tests/test_debate_orchestrator.py -v`

## Design

### `DebateResult` dataclass

File: `forge_agent/core/debate_orchestrator.py`

```python
@dataclass
class DebateResult:
    verdict: str          # "consensus" | "maintained_disagreement"
    final_output: dict    # specialist_output (possibly updated)
    rounds: int           # always ≥ 1
    critiques: list       # list of raw critique dicts from antagonist
```

### `DebateOrchestrator` class

```python
class DebateOrchestrator:
    """Drives one or more rounds of specialist→antagonist debate.

    Does NOT import from forge-learning. Self-contained within forge_agent.
    """

    MAX_ROUNDS: int = 3

    def __init__(
        self,
        specialist: Any,   # AntagonistAgent subclass — uses .critique() method
        antagonist: Any,   # AntagonistAgent subclass — uses .critique() method
    ) -> None:
        self._specialist = specialist   # stored and used — P2 compliant
        self._antagonist = antagonist   # stored and used — P2 compliant

    def run_debate(
        self,
        specialist_output: dict,
        context: dict,
    ) -> DebateResult:
        """Run up to MAX_ROUNDS rounds.

        Round protocol:
          1. Antagonist critiques specialist_output.
          2. If severity=="fatal" → maintain_disagreement flag set.
          3. If no fatal critiques or max rounds reached → consensus.
        """
```

### `DebateOrchestrator.run_debate()` algorithm

```
critiques_all = []
maintained = False
for round_num in 1..MAX_ROUNDS:
    critique = antagonist.critique(specialist_output, context)
    critiques_all.append(critique)
    if critique["severity"] == "fatal":
        maintained = True
        break          # one fatal ends debate immediately
    # no fatal → consensus after first clean round
    break
verdict = "maintained_disagreement" if maintained else "consensus"
return DebateResult(verdict=verdict, final_output=specialist_output,
                    rounds=round_num, critiques=critiques_all)
```

Note: Both `self._specialist` and `self._antagonist` are parameters stored on
`self` and referenced in `run_debate` — P2 rule satisfied. The specialist object
is passed to the orchestrator because future rounds may ask the specialist to
respond; the current single-round implementation calls `antagonist.critique()`.

### Pipeline changes

File: `forge_agent/core/pipeline.py`

1. Add `debate_verdict: str | None = None` field to `TaskResult` dataclass.
2. Add optional `debate_orchestrator: Any = None` parameter to `PipelineRunner.__init__()`.
   Store as `self._debate_orchestrator`. Document it in the docstring.
3. In `run()`, after Phase 5 (`specialist_output = self._run_phase_specialist(...)`)
   add Phase 5b:

```python
# Phase 5b — debate (optional; only if antagonist is configured)
debate_verdict: str | None = None
if self._debate_orchestrator is not None:
    debate_result = self._debate_orchestrator.run_debate(
        specialist_output, blackboard
    )
    debate_verdict = debate_result.verdict
    blackboard["debate.verdict"] = debate_verdict
    blackboard["debate.rounds"] = debate_result.rounds
    blackboard["debate.fatal_critique"] = any(
        c.get("severity") == "fatal" for c in debate_result.critiques
    )
```

4. In `_assemble_output()`, pass `debate_verdict` through and include it in
   `TaskResult`. If `debate_verdict == "maintained_disagreement"` and
   `blackboard.get("debate.fatal_critique")` is True, override `status = "disputed"`.

5. Update `_assemble_output` signature to accept `debate_verdict: str | None = None`.

## Known Risks

- `TaskResult` currently has no `debate_verdict` field. Adding it with
  `field(default=None)` is backward compatible — all existing tests that
  construct `TaskResult` without `debate_verdict` will still compile.
- The `specialist` object stored in `DebateOrchestrator` is not called in the
  current single-round implementation. It is stored (not silently dropped) for
  future multi-round specialist response rounds. This satisfies P2 because the
  attribute is documented and accessible; it is not accepted and discarded.
- `forge-learning` `DebateLifecycle` uses sync `anthropic.Anthropic` directly.
  The new orchestrator avoids this dependency entirely and delegates all LLM calls
  to the antagonist agent's `_generate_critique()`. This keeps debate logic
  model-agnostic and testable without API keys.
