## Purpose

Provides system safety analysis and systems engineering discipline for FORGE
projects. Covers:

- Failure Mode and Effects Analysis (FMEA / FMECA)
- Fault Tree Analysis (FTA) — Boolean logic, cut sets, MCS
- Hazard Identification and Risk Assessment (HIRA / HAZOP)
- Requirements traceability (requirement → design → test)
- Redundancy and fault tolerance architecture
- Safety case development (structured argument, GSN notation)
- Certification pathway identification (FAA, EASA, MIL-STD-882, DO-178C/254, ARP4761)
- Design Assurance Level (DAL) / Safety Integrity Level (SIL) allocation

---

## Preconditions

1. System description and mission profile (from `system-decomposition`)
2. Failure consequences defined (mission loss, property damage, injury, fatality)
3. Requirements tree available (R-XXX records)
4. Component list with criticality flags

If safety-critical functions are undefined, flag:
`[SAFETY BLOCKED: CRITICAL FUNCTIONS UNDEFINED]` before analysis.

## Step 1 — Hazard Identification

Enumerate all system hazard categories:

| Hazard ID | Hazard Description | Initiating Event | Consequence | Severity |
|---|---|---|---|---|
| H-001 | Uncommanded propulsion loss | Motor failure | Vehicle crash | Catastrophic |
| H-002 | Loss of control link | RF interference | Fly-away | Critical |
| H-003 | Battery over-temperature | Cell failure | Fire | Critical |
| H-004 | Payload release during flight | Latch failure | Dropped object | Critical |

**Severity classification (MIL-STD-882E):**

| Level | Category | Description |
|---|---|---|
| I | Catastrophic | Death, loss of system |
| II | Critical | Severe injury, major mission loss |
| III | Marginal | Minor injury, degraded mission |
| IV | Negligible | No injury, minimal mission effect |

---

## Step 2 — FMEA

For each component, enumerate failure modes:

```
Component: Main propulsion motor (M-001)
Failure Mode: Open-circuit winding
Effect (local): Motor stops producing thrust
Effect (system): Vehicle yaw/pitch asymmetry → potential loss of control
Detection: FC detects throttle command vs. current mismatch within 50 ms
Mitigation: Redundant motor controller; motor mixing to compensate 1-motor-out
Residual risk: Reduced hover margin; land immediately
Criticality: 2 (Critical, probable)
```

---

## Step 3 — Fault Tree Analysis

Construct FTA for top-level hazard H-001 (loss of propulsion):

```
                [Loss of All Thrust]
                       |
              ┌────────┴────────┐
         [OR gate]           [OR gate]
         |       |           |       |
    [M1 fails] [M2 fails] [M3 fails] [M4 fails]
         |
    [Open circuit] OR [Short circuit] OR [ESC failure]
```

Compute minimal cut sets (MCS). Any single-point failure (MCS size = 1)
for a Catastrophic hazard requires redundancy or mitigation.

Probability targets (ARP4761 / MIL-STD-882E):

| Hazard Level | Max probability per flight hour |
|---|---|
| Catastrophic | < 10⁻⁹ |
| Critical | < 10⁻⁷ |
| Marginal | < 10⁻⁵ |
| Negligible | < 10⁻³ |

---

## Step 4 — Redundancy Architecture

For each Catastrophic and Critical hazard with single-point failures:

- Specify redundancy type (active-active, active-standby, voted/TMR)
- State switchover time and detection method
- Verify that common-cause failures are addressed (different manufacturers,
  physical separation, independent power rails)

---

## Step 5 — Requirements Traceability

For each safety requirement (SR-XXX):

```
SR-001: Vehicle shall not enter uncontrolled flight following single motor failure.
  → Design: Motor mixing algorithm, minimum 3-motor-flight mode
  → V&V: HIL simulation with motor kill injection; flight test (range/tether)
  → Status: OPEN — HIL test not yet run
```

Flag any SR with status OPEN before design closure.

## Mandatory Output Fields

- `findings` — hazard list, FMEA table, FTA top events, MCS
- `assumptions` — failure rate data sources, mission profile
- `what_would_falsify` — observed failure rate exceeding FTA probability budget
- `gaps_identified` — undefined critical functions, missing failure rates
- `open_requirements` — list of SR-XXX with status OPEN
- `safety_critical_flags` — components requiring extra verification

If any Catastrophic hazard has a single-point MCS with no mitigation, emit:
`[SAFETY CRITICAL — HALT DESIGN]` and escalate to user.

## What This Skill Does NOT Do

- Does not certify the design — flags the certification pathway
- Does not perform quantitative reliability without sourced failure rate data
- Does not replace DO-178C/DO-254 software/hardware assurance process
