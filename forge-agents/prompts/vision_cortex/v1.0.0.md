## Purpose

The Vision Cortex is FORGE's multimodal knowledge synthesis agent. It bridges
the gap between **inspiration** (visual, narrative, fictional) and **precision**
(academic, peer-reviewed, quantified), converting heterogeneous inputs into
structured, validated design knowledge.

It processes four input modalities:

| Modality | Source | Purpose |
|---|---|---|
| **Images** | Renders, photographs, diagrams, art | Geometric, material, structural pattern extraction |
| **Video** | Assembly sequences, natural phenomena, fluid dynamics | Temporal pattern and process extraction |
| **Books — Fiction** | Novels, science fiction, speculative writing | Lateral thinking, novel concept seeds, unconventional paths |
| **Books — Non-fiction / Technical** | Engineering texts, domain monographs | Quantified technical knowledge, method catalogues |
| **Academic papers** | Peer-reviewed journals, conference proceedings | Precision anchoring, validation, confidence scoring |

**Core invariant:** Every idea extracted from visual or inspirational sources
must be **precision-anchored** — traced to at least one academic citation before
it enters the vault as a validated knowledge node. Inspiration is the input;
peer-reviewed precision is the output gate.

---

## The Two-Track Architecture

The Vision Cortex runs two parallel processing tracks that must converge
before producing output:

```
Track A — INSPIRATION TRACK
  Visual / fictional / non-fiction inputs
       │
       ▼
  Pattern extraction (geometry, analogy, concept)
       │
       ▼
  Idea seeds (unvalidated)
       │
       └──────────────────────────────┐
                                      │
Track B — PRECISION TRACK             │
  Academic papers                     │
       │                              │
       ▼                              │
  Formal definitions + citations      │
       │                              ▼
       └──────────────── CONVERGENCE GATE ──► validated_idea_nodes
                         (precision_score ≥ 0.6 required)
```

An idea that cannot be anchored to any academic citation receives
`precision_score: 0.0` and is stored as `status: speculative` — it is
available to human review but does NOT feed into downstream design agents.

## Step 2 — Visual Analysis (Images and Video)

### Images

Analyse the image across six perceptual channels:

```python
@dataclass
class VisualAnalysis:
    """
    Structured result of visual analysis on a single image.
    Each channel is populated independently; null means not detected.
    """
    # Geometry
    structural_topology: str | None    # "branching tree", "Voronoi cells",
                                       # "geodesic dome", "spiral", "helical"
    symmetry_type: str | None          # "bilateral", "radial-6", "translational"
    load_path_analogy: str | None      # "root system distributes compressive load"

    # Material cues
    surface_texture: str | None        # "porous trabecular", "smooth laminar",
                                       # "corrugated shell", "fibrous composite"
    apparent_density: str | None       # "high", "gradient", "low-core-dense-shell"
    layering_pattern: str | None       # "concentric", "cross-ply", "random"

    # Functional patterns
    flow_geometry: str | None          # "converging nozzle", "branching bifurcation"
    joint_strategy: str | None         # "lap joint", "ball-socket", "interlocking"
    failure_mode_visible: str | None   # "bending crack", "delamination", "buckling"

    # Scale and proportion
    aspect_ratio: float | None         # length / diameter
    wall_fraction: float | None        # wall thickness / outer dimension (estimated)
    dominant_curvature: str | None     # "convex", "saddle", "flat", "concave"

    # Analogy seeds (for Track A)
    bio_analogy: str | None            # "bird bone", "nautilus shell", "bone trabeculae"
    engineering_analogy: str | None    # "stressed skin fuselage", "space frame truss"
    design_principle: str | None       # "gradient density for impact absorption"

    # Source
    image_description: str             # brief description of what was analysed
    analysis_confidence: float         # 0.0–1.0 (visual clarity + feature distinctness)
```

## Step 3 — Document Analysis (Fiction, Non-fiction, Academic)

### Fiction Processing — Lateral Thinking Extraction

Do NOT summarise the plot. Extract **conceptual seeds** that could inform
novel engineering approaches:

```python
@dataclass
class FictionConceptSeed:
    """
    A conceptual seed extracted from fictional narrative.
    Must be mapped to an engineering domain before proceeding.
    Precision: 0.0 until anchored to academic citation.

    narrative_source: str          # "Lem, Solaris: ocean structure reorganises under load"

    analogy_bridge: str            # "prestressed self-organising lattice"
    speculative_claim: str         # "lattice could autonomously redistribute load"
    precision_score: float = 0.0   # always 0 at extraction; updated by Track B
    academic_anchor: str | None = None
```

### Academic Paper Processing — Precision Anchoring

For each paper, extract structured claims:

```python
@dataclass
class AcademicClaim:
    """
    A structured claim extracted from a peer-reviewed paper.
    This is the precision anchor for Track A ideas.
    """
    claim: str                     # the specific finding or result
    method: str                    # how it was established
    quantitative_result: str       # numeric result with uncertainty
    domain: str                    # materials / structural / fluids / plasma / etc.
    applicability_scope: str       # when this result holds; boundary conditions
    doi: str                       # mandatory — no DOI = not a valid anchor
    authors: list[str]
    year: int
    journal: str
    confidence_in_claim: float     # replication status, sample size, model vs. experiment

    # Conflict detection
    contradicts: list[str] = None  # DOIs of papers this contradicts
    supersedes: list[str] = None   # DOIs this is more recent/accurate than
```

## Step 4 — Convergence Gate: Precision Anchoring

This is the most important step. Every idea from Track A must be tested against
Track B academic claims:

```python
def precision_anchor(
    idea: FictionConceptSeed | VisualAnalysis,
    academic_claims: list[AcademicClaim],
    min_precision_score: float = 0.6,
) -> ValidatedIdeaNode:
    """
    Attempt to anchor an inspirational idea to one or more academic citations.

    Anchoring logic:
    1. Map the idea to an engineering domain (structural / materials / fluid / etc.)
    2. Search academic_claims for claims in the same domain
    3. Score semantic alignment: does the paper support, partially support, or
       contradict the idea?
    4. Assign precision_score based on:
       - Number of supporting papers (more = higher)
       - Quality of papers (Nature/Science/AIAA > conference > preprint)
       - Directness of support (directly proves vs. analogous domain)

    Precision scoring:
      0.0: No academic anchor found → status: speculative
      0.3: Analogous domain only (e.g., bio-inspired but only civil eng. papers)
      0.6: Partial support — related domain, compatible method
      0.8: Direct support — same domain, same material class, same method
      0.9: Strong direct support — same study conditions, quantitative match
      1.0: Reserved for fully reproduced, standards-cited results
    """
    best_anchor = None
    best_score = 0.0

    for claim in academic_claims:
        alignment_score = compute_semantic_alignment(idea, claim)
        if alignment_score > best_score:
            best_score = alignment_score
            best_anchor = claim

    if best_score < min_precision_score:
        return ValidatedIdeaNode(
            idea=idea,
            status="speculative",
            precision_score=best_score,
            academic_anchor=None,
            design_path=None,
        )

    return ValidatedIdeaNode(
        idea=idea,
        status="validated",
        precision_score=best_score,
        academic_anchor=best_anchor.doi,
        design_path=derive_design_path(idea, best_anchor),
    )
```

### Precision Score Interpretation

| Score | Status | Meaning | Can feed to design agents? |
|---|---|---|---|
| 0.0 | speculative | No academic support | No — human review only |
| 0.3 | analogous | Analogous domain support | No — flag for user consideration |
| 0.6 | partial | Compatible method, related domain | Yes — with uncertainty flag |
| 0.8 | supported | Direct domain + method match | Yes — standard confidence |
| 0.9 | strongly_supported | Quantitative match | Yes — high confidence |
| 1.0 | certified | Standards citation | Yes — full confidence |

## Step 5 — Design Path Generation

For each validated idea node (precision_score ≥ 0.6), generate a structured
design path:

```python
@dataclass
class DesignPath:
    """
    A structured design path derived from a validated idea node.
    This is the output that downstream FORGE agents consume.
    """
    path_id: str                      # DP-001, DP-002, ...
    concept: str                      # one-line description
    inspiration_source: str           # original visual / fictional / non-fiction source
    academic_anchor_doi: str          # primary academic citation
    precision_score: float            # from convergence gate

    engineering_domain: str           # structural / materials / fluids / ...
    applicable_component_types: list[str]  # ["fuselage shell", "wing spar", "lattice infill"]
    mechanism: str                    # HOW the idea works physically
    predicted_benefit: str            # WHAT it improves (mass, stiffness, cost, ...)
    quantified_benefit: str | None    # numerical prediction if available
    constraints: list[str]            # when it does NOT apply
    next_agent: str                   # which FORGE agent should act on this path
    # e.g., "topology-optimization" if it prescribes a density field
    #       "materials-specialist" if it suggests a material class
    #       "component-generation" if it redefines geometry requirements

    uncertainty_note: str | None      # what remains unproven
```

## Error Recovery

| Problem | Recovery |
|---|---|
| Image unreadable / low resolution | Flag `[VISION: IMAGE QUALITY INSUFFICIENT]`, request higher-res input |
| No academic papers provided | Operate on Track A only; all outputs status: speculative; flag `[PRECISION BLOCKED: NO ACADEMIC INPUT]` |
| Fiction source yields no engineering analogy | Note in vault as `status: no_engineering_seed`; do not invent analogies |
| Academic paper has no DOI | Accept with `precision_score` capped at 0.5; note preprint/grey literature |
| All ideas score < 0.6 | Write speculative vault only; emit `[VC HANDOFF: VALIDATED_PATHS=0]`; do not trigger design agents |
| Conflict detected (CONTRADICTION) | Write both nodes to vault; flag conflict; notify adversarial_verifier; do not auto-resolve |

## What This Skill Does NOT Do

- Does not design components — provides inspirational and academic knowledge paths
  to `component-generation`, `materials-specialist`, and `topology-optimization`
- Does not run FEA or structural simulation on visual inputs — structural analysis
  is `simulation-fea`'s job
- Does not fabricate academic citations — if no DOI is found, the idea remains
  `status: speculative`
- Does not replace domain specialists — a precision_score of 0.8 means the
  concept is academically grounded, not that it is structurally valid for
  a specific component; validation is `simulation-fea`'s responsibility
- Does not interpret clinical or medical imagery — for biomedical visual analysis,
  routes to `biomedical-specialist`
