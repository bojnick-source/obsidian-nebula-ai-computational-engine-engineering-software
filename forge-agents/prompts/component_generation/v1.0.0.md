# Component Generation Skill — v1.0.0

**Agent:** component_generation
**Version:** 1.0.0
**Role:** workflow / component-design
**Output contract:** `docs/contracts/agent-output-contract.md` (output_type: component-spec)
**Precedes:** simulation-fea, assembly, cad-export, topology-optimization
**Follows:** system-decomposition (consumes `decomposition_handoff`)
**Triggered by:** `decomposition_handoff` present + user says proceed;
  phrases like "generate the component", "design the part",
  "spec out the [name]", "create geometry for"

---

## Purpose

Produces a fully-specified component definition: parametric geometry, material
selection with sourced properties, manufacturing method with process parameters,
and a quality inspection plan. Output is written to the vault and is the
required input to `simulation-fea` and `assembly`.

Works symbiotically with `system-decomposition` — decomposition provides the
tree and budgets; component-generation fills in each leaf node with enough
precision to manufacture or simulate it.

---

## Preconditions

Required before starting. Halt and ask if missing:

1. **Component ID and name** — from the `decomposition_handoff` block
   (e.g., `C-001 Fuselage shell`)
2. **Mass budget** — hard upper limit in kg
3. **Material hint** — even if just "carbon fiber" or "aluminum";
   drives the entire design space
4. **Geometric envelope** — max dimensions (L × W × H or diameter × length)
5. **Load conditions** — at minimum: what loads this component must carry,
   in what direction
6. **Interface requirements** — what this component connects to
   (from the IF-XXX records)

If load conditions are absent, do not proceed with DESIGN or HYBRID mode.
Produce a placeholder spec and flag `[LOADS REQUIRED]`.

---

## Mode Selection

Determine mode at the start. Ask the user if unclear:

| Mode | Use When | Output |
|---|---|---|
| **DESIGN** | Geometry doesn't exist yet; define shape and dimensions | Parametric geometry + PicoGK script |
| **SPECIFY** | Geometry already exists (COTS or provided); need material + process specs | Material property sheet + process card |
| **HYBRID** | Both: generate geometry AND select material/process | Both outputs |

Default to **HYBRID** for novel structural components.
Default to **SPECIFY** for COTS items (motors, fasteners, bearings).

## Step 1 — Load Conditions Analysis

Before generating anything, establish the load envelope. Use `specialist_ME`
(via model router) to produce:

```
Component: C-001 Fuselage Shell
Load Cases:
  LC-001  Flight loads     Fz = 60 N (1.5g with 4 kg payload), Mx = 8 N·m (aileron)
  LC-002  Landing impact   Fz = 300 N (3g at 1 m/s sink rate, 2× safety factor)
  LC-003  Ground handling  Fx = 20 N (drop, shear at attachment points)
Critical case: LC-002 (landing impact)
Required safety factor: 2.0 (DARPA LIFT, unmanned, test article)
Material yield stress must exceed: σ_y > 300N / A_section × 2.0
```

If the ME specialist flags any load case as indeterminate (requires system-level
simulation to determine), note it as
`[LOAD INDETERMINATE: requires simulation-fea first]` and switch to SPECIFY mode.

## Step 2A — DESIGN Mode: Parametric Geometry

Produce geometry as PicoGK Python parameters, not as raw mesh. Parameters must
drive the geometry — no hardcoded magic numbers.

```python
# C-001 Fuselage Shell — parametric definition
# All dimensions in meters unless noted. All masses in kg.

class FuselageShellParams:
    # Envelope (from decomposition)
    length_m: float = 0.85
    max_diameter_m: float = 0.12

    # Structural wall
    wall_thickness_m: float = 0.003      # 3 mm CFRP laminate
    n_plies: int = 4                      # [0°/90°/90°/0°] layup

    # Interfaces (from IF-001, IF-002)
    wing_root_spar_cutout_diameter_m: float = 0.025
    motor_mount_bolt_pattern_m: float = 0.035  # bolt circle diameter
    n_motor_mounts: int = 4

    # Payload bay
    payload_bay_length_m: float = 0.22
    payload_bay_width_m: float = 0.10
    payload_bay_door_hinge_offset_m: float = 0.015

    # Derived (computed, not free parameters)
    @property
    def inner_diameter_m(self) -> float:
        return self.max_diameter_m - 2 * self.wall_thickness_m

    @property
    def cross_section_area_m2(self) -> float:
        import math
        return math.pi * (self.max_diameter_m**2 - self.inner_diameter_m**2) / 4
```

Rules:

- Every dimension must trace back to a requirement or interface definition.
  Write the traceability as a comment.
- No "eyeballed" dimensions. If a value is estimated, tag it `# EST: [reasoning]`.
- Every parameter that affects mass must be listed; they will be summed for
  mass verification.
- Interface dimensions must exactly match the values in the IF-XXX record.
  If there is a conflict, flag it — never resolve silently.

Then pass these parameters to the `picogk-geometry` skill for solid model
generation.

## Step 2B — SPECIFY Mode: Material + Process Card

```yaml
material_spec:
  component_id: C-001
  material_designation: "Toray T300 / Epoxy 3501-6"
  material_form: "unidirectional prepreg, 0.125mm ply thickness"
  supplier_hint: "Toray, Hexcel, or equivalent"

  mechanical_properties:
    E1_GPa: 135        # fiber direction modulus  [source: Toray T300 datasheet]
    E2_GPa: 9.0        # transverse modulus
    G12_GPa: 5.0       # shear modulus
    nu12: 0.25         # Poisson ratio
    Xt_MPa: 1500       # tensile strength, fiber
    Xc_MPa: 1200       # compressive strength, fiber
    Yt_MPa: 40         # transverse tensile
    S_MPa: 68          # in-plane shear
    rho_kg_m3: 1600    # density

  source: "Toray T300 product data sheet, accessed 2024"
  confidence: high     # direct from manufacturer datasheet

  allowable_vs_requirement:
    critical_load_case: LC-002
    required_strength_MPa: 150.0    # from load analysis
    allowable_strength_MPa: 1200.0  # Xc (compression governs in landing)
    margin_of_safety: 7.0           # ≥ 0.0 required ✅

manufacturing_spec:
  method: "wet layup / vacuum bag cure"
  cure_cycle: "60°C for 4h, then 120°C for 2h"
  tooling: "foam mandrel, removable"
  n_plies: 4
  layup_sequence: "[0/90/90/0]"
  surface_finish: "peel ply on inner, 220 grit sand + 2K epoxy primer outer"
  critical_operations:
    - "Inspect for delamination by tap test after cure"
    - "Verify cutout diameters within ±0.1 mm before bonding"

quality_plan:
  dimensional_checks:
    - "Max OD: 120.0 ± 0.5 mm"
    - "Length: 850 ± 1.0 mm"
    - "Wing spar cutout: 25.0 ± 0.1 mm"
  structural_acceptance:
    - "Proof load to 150% limit: 450 N axial for 5 min, no audible crack"
  mass_acceptance:
    - "As-built mass: ≤ 0.45 kg"
```

**Critical:** Every mechanical property must cite a source. "Engineering
judgment" or "assumed" are not valid sources for structural properties. If a
property cannot be sourced, flag it `[NEEDS TEST DATA]` and mark the component
as `status: unverified` in the vault.

## Step 3 — Mass Verification

Compute as-designed mass and compare to budget:

```
C-001 Mass Estimate
  Shell volume: π/4 × (0.12² - 0.114²) × 0.85 m³ = 5.42 × 10⁻⁴ m³
  Density:      1600 kg/m³
  Raw mass:     0.867 kg
  ⚠️ EXCEEDS BUDGET (budget: 0.45 kg)

  Resolution options:
    A) Reduce to 2 plies — drops to 0.43 kg but σ_allow drops to 600 MPa (MS=3.0, still OK)
    B) Use T700 UD (rho=1580, E=230 GPa) — minimal mass savings
    C) Accept 2-ply with local doubler at cutouts and attachment points
  → Recommend Option A+C. Flagging for user approval.
```

If as-designed mass exceeds budget by more than 15%, stop and escalate — do not
silently thin the walls.

## Error Recovery

| Problem | Recovery |
|---|---|
| Mass over budget | Compute delta, present 3 resolution options, ask user to choose |
| Cannot source material properties | Flag `[NEEDS TEST DATA]`, use knockdown factor (×0.85 on handbook value), mark unverified |
| Interface dimension conflict | Stop. Show the conflict explicitly. Never pick a winner silently |
| Load case is indeterminate | Switch to SPECIFY only, flag geometry as `[LOADS TBD]` |
| PicoGK params produce non-manufacturable geometry | Flag the issue, suggest design change, do not proceed to FEA |
| COTS item has no public datasheet | Use worst-case handbook values, mark `[SPEC UNCONFIRMED]` |

## What This Skill Does NOT Do

- Does **not** run FEA (that is `simulation-fea`)
- Does **not** check assembly fit (that is `assembly`)
- Does **not** generate STL/STEP files (that is `cad-export`)
- Does **not** perform topology optimization (that is `topology-optimization`)
