## Purpose

Provides mathematical optimization formulation, algorithm selection, and
implementation guidance for FORGE agents that need to solve optimization
problems. Consumed by:

- `topology-optimization` — for SIMP sensitivity formulation
- `controls-specialist` — for LQR, MPC, trajectory optimization
- `ee-specialist` — for power budget allocation, antenna placement
- Any agent facing a "minimize X subject to constraints on Y" problem

Responsibilities:

- Classify the problem (convex/nonconvex, continuous/integer, smooth/non-smooth)
- Select the appropriate algorithm and solver
- Formulate the problem in standard form
- Implement or specify the implementation
- Verify optimality conditions (KKT, gradient check)

## Step 1 — Problem Classification

Before selecting an algorithm, classify the problem:

```python
class OptimizationProblem:
    """Classification of an optimization problem."""

    objective_type: str       # "linear" | "quadratic" | "nonlinear" | "black_box"
    constraint_type: str      # "linear" | "nonlinear" | "integer" | "mixed"
    convexity: str            # "convex" | "nonconvex" | "unknown"
    smoothness: str           # "smooth" (C²) | "C1" | "Lipschitz" | "non-smooth"
    n_variables: int
    n_constraints: int
    problem_class: str        # LP / QP / SOCP / SDP / NLP / MILP / MINLP
```

Classification determines the algorithm family:

| Class | Algorithm family | Solver |
|---|---|---|
| LP | Simplex, interior point | scipy.optimize.linprog, GLPK, HiGHS |
| QP | Active set, interior point | OSQP, quadprog, CVXPY |
| SOCP / SDP | Interior point | CVXPY + SCS / MOSEK |
| Convex NLP | Gradient descent, Newton, L-BFGS | scipy.optimize.minimize |
| Nonconvex NLP | SQP, trust region, augmented Lagrangian | scipy.optimize (SLSQP, trust-constr) |
| MILP / MINLP | Branch-and-bound, B&C | PuLP + CBC, Pyomo + CPLEX/Gurobi |
| Black-box / noisy | Nelder-Mead, CMA-ES, Bayesian | scipy Nelder-Mead, cma library |

## Step 2 — Standard Form Formulation

Express the problem in standard form. Example for NLP:

```
minimize    f(x)
subject to  g_i(x) ≤ 0,    i = 1, ..., m    (inequality constraints)
            h_j(x) = 0,    j = 1, ..., p    (equality constraints)
            x ∈ ℝⁿ
```

Write out f, g, h explicitly with variable definitions:

```python
# Example: topology optimization sensitivity update
# minimize    compliance  C = F^T × u
# subject to  sum(x_e × V_e) / V_total ≤ volfrac   (volume constraint)
#             0 < x_min ≤ x_e ≤ 1                   (density bounds)
#
# Variable: x_e ∈ [x_min, 1] for e = 1, ..., N_elements
# x_min = 1e-9 to prevent singularity

def compliance(x, u, K_global):
    return float(u.T @ K_global @ u)

def volume_constraint(x, V_e, V_total, volfrac):
    return (x @ V_e) / V_total - volfrac
```

## Step 3 — Optimality Conditions

State the KKT conditions for the problem and verify them at the solution:

```python
def check_kkt(x_opt, grad_f, grad_g, lambda_opt, mu_opt):
    """
    KKT stationarity: ∇f + Σλ∇g + Σμ∇h = 0
    Primal feasibility: g(x) ≤ 0, h(x) = 0
    Dual feasibility: λ ≥ 0
    Complementary slackness: λ_i × g_i(x) = 0
    """
    stationarity = grad_f + sum(l * dg for l, dg in zip(lambda_opt, grad_g))
    primal_feas = all(gi <= 1e-6 for gi in g_values)
    dual_feas = all(l >= 0 for l in lambda_opt)
    comp_slack = all(abs(l * g) < 1e-8 for l, g in zip(lambda_opt, g_values))
    return stationarity, primal_feas, dual_feas, comp_slack
```

If KKT conditions are not satisfied at the reported solution, the solver
has not converged — report `convergence_status: failed`.

## Step 4 — Gradient Verification

For gradient-based methods, verify analytic gradients against finite differences:

```python
def check_gradient(f, x, grad_f, eps=1e-5):
    """Compare analytic gradient to central finite difference."""
    import numpy as np
    fd_grad = np.zeros_like(x)
    for i in range(len(x)):
        e = np.zeros_like(x)
        e[i] = eps
        fd_grad[i] = (f(x + e) - f(x - e)) / (2 * eps)
    error = np.max(np.abs(grad_f - fd_grad))
    return error, fd_grad
```

Relative error > 1e-4 indicates a gradient implementation error.

- Does not substitute for commercial solver licensing (CPLEX, Gurobi, MOSEK)
