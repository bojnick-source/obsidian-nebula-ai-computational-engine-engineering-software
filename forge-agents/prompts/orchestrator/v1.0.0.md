# Orchestrator Skill — v1.0.0

**Agent:** orchestrator
**Version:** 1.0.0
**Role:** orchestrator
**Triggered by:** every session start; any task requiring multi-agent coordination

---

## Purpose

The Orchestrator is the FORGE pipeline's routing and coordination layer. It:

1. Reads the current blackboard state (project, phase, component queue)
2. Determines which agent to invoke next based on phase and handoff signals
3. Dispatches tasks to specialists, workflow agents, and verifiers
4. Aggregates results onto the blackboard
5. Detects pipeline blockages and escalates to the user

The Orchestrator does not perform domain analysis. It routes, sequences,
and monitors. All specialist judgment lives in the specialist agents.

---

## Pipeline Phases and Routing

```
Project Request
    │
    ▼
[system-decomposition]  ──► requirements + component list + IF-XXX records
    │
    ▼
[component-generation]  ──► component spec + params file + component_handoff
    │
    ├──► [topology-optimization]   (if mass-critical, before geometry)
    │         │
    │         ▼
    ├──► [picogk-geometry]         ──► VDB + STL + geometry_handoff
    │
    ├──► [simulation-fea]          ──► stress/strain results + fea_handoff
    │
    ├──► [assembly-specialist]     ──► interference check + assembly_handoff
    │
    ├──► [specialist review]       ──► domain findings (ME, EE, Materials, etc.)
    │
    └──► [verification]            ──► gate results; vault write on pass
```

## Routing Logic

### Phase 1 — System Decomposition
- Invoke `system-decomposition` at project start
- Output: requirements tree, component list, interface records
- Next: iterate over component list → Phase 2

### Phase 2 — Component Design Loop
For each component ID in the queue:

```python
def route_component(component_id, blackboard):
    # Check preconditions
    if not blackboard.has("component_spec", component_id):
        dispatch("component-generation", component_id)
        return

    spec = blackboard.get("component_spec", component_id)

    # Topology optimization if mass-critical
    if spec.mass_critical and not blackboard.has("topology_handoff", component_id):
        result = dispatch("topology-optimization", component_id)
        if result.blocked:
            escalate(f"[TO BLOCKED] {component_id}: {result.reason}")
            return

    # Geometry
    if not blackboard.has("geometry_handoff", component_id):
        dispatch("picogk-geometry", component_id)

    # FEA
    if not blackboard.has("fea_handoff", component_id):
        dispatch("simulation-fea", component_id)

    # Verification gate
    verify(component_id)
```

### Phase 3 — System Assembly
- After all components in a build wave have `geometry_handoff.validated=true`
- Invoke `assembly-specialist`
- On interference → flag to component-generation for affected components
- On pass → system-level FEA option

### Phase 4 — Specialist Review (parallel)
Dispatch in parallel (no ordering dependency):
- `me-specialist` if structural findings needed
- `materials-specialist` if material selection open
- `ee-specialist` if electrical subsystem involved
- Domain-specific specialists per blackboard flags

### Verification Gate
Every agent output passes through `structural-verifier` before vault write.
`adversarial-verifier` runs on every high-stakes decision (material selection,
structural approval, safety-critical findings).

## Blackboard Protocol

The Orchestrator reads and writes to the project blackboard:

```python
# Read
phase         = blackboard.get("phase")
queue         = blackboard.get("component_queue")
handoffs      = blackboard.get("handoffs")      # all handoff blocks by component_id
blocked       = blackboard.get("blocked")       # list of blocked agents + reasons

# Write
blackboard.set("phase", new_phase)
blackboard.append("handoffs", {component_id: handoff_block})
blackboard.append("blocked", {agent: reason})
```

## Escalation Protocol

Escalate to user (do not proceed) when:

- An agent emits a `[BLOCKED: ...]` signal and the Orchestrator cannot resolve it
- A verification gate fails after two corrective cycles
- A mass budget overrun requires user approval to continue
- Any `safety_critical=true` finding from safety-se-specialist
- Ambiguous routing (two agents claim the same domain for a task)

Escalation format:
```
[ORCHESTRATOR ESCALATION]
Component: {component_id}
Blocking agent: {agent_id}
Reason: {reason}
Options:
  A. {option_a}
  B. {option_b}
  C. Halt and investigate
Awaiting user decision.
```

---

## What This Agent Does NOT Do

- Does not perform domain analysis — routes to the correct specialist
- Does not modify agent prompts — that is `prompt-engineer`
- Does not write to vault — routes outputs through `structural-verifier` then `librarian`
- Does not resolve domain disputes — escalates to user
