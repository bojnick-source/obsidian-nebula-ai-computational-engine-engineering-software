# System Decomposition Skill — v1.0.0

**Agent:** system_decomposition
**Version:** 1.0.0
**Role:** workflow / project-kickoff
**Output contract:** `docs/contracts/agent-output-contract.md` (output_type: decomposition)
**Runs before:** component-generation, simulation-fea, assembly_specialist
**Triggered by:** new project kickoff, "break this down", "what are the subsystems",
  "build plan", "component tree", "WBS"

---

## Purpose

Transforms a high-level system description into a fully structured component
hierarchy with interfaces, mass/volume/power budgets, and a sequenced build plan.
This is always the **first skill run** in any FORGE engineering project.
Nothing else starts until decomposition produces a verified tree and writes it
to the vault.

---

## Preconditions

Check these before doing anything else. Stop and ask the user if any are missing:

1. **System description** — at minimum: what the system does, primary
   performance goal, one or more hard constraints (mass, envelope, power, cost).
2. **Top-level requirements** — at least three measurable requirements with
   units: e.g., payload capacity [kg], total mass [kg], operating altitude [m],
   design life [cycles].
3. **Project name** — used for vault path naming. If not given, derive from
   system name and confirm with user.

If requirements are vague (e.g., "make it lightweight"), produce three candidate
requirement interpretations and ask the user to pick or modify before proceeding.

---

## Step 1 — Extract System Context

Parse the user's description and create a structured context block in a
`<system_context>` XML block so downstream agents can parse it:

```xml
<system_context>
  <project_name>Aladdin-3B</project_name>
  <system_type>fixed-wing_VTOL_drone</system_type>
  <primary_mission>cargo_delivery</primary_mission>
  <top_level_requirements>
    <req id="R001" type="mass"      value="≤6.1" units="kg"
         rationale="DARPA LIFT payload ratio">Total aircraft mass ≤ 6.1 kg for 1 kg payload</req>
    <req id="R002" type="endurance" value="≥30"  units="min"
         rationale="mission profile"/>
    <req id="R003" type="envelope"  value="1.2x0.8x0.3" units="m"
         rationale="transport constraint"/>
  </top_level_requirements>
  <hard_constraints>
    <constraint>gasoline-electric hybrid propulsion</constraint>
    <constraint>foldable for transport</constraint>
  </hard_constraints>
</system_context>
```

If you cannot fill in `system_type`, `primary_mission`, and at least two
requirements with units, stop and ask before continuing.

---

## Step 2 — Generate Component Tree

Produce a three-level hierarchy minimum (System → Subsystem → Component).
Use this exact indented structure so it can be parsed programmatically:

```
[System]  Aladdin-3B                       mass_budget: 6.1 kg   100%
  [SS-01] Airframe                          mass_budget: 1.8 kg   29.5%
    [C-001] Fuselage shell                  mass_budget: 0.45 kg
    [C-002] Main wing (×2, foldable)        mass_budget: 0.55 kg
    [C-003] Tail assembly (V-tail)          mass_budget: 0.25 kg
    [C-004] Landing gear                    mass_budget: 0.18 kg
    [C-005] Motor mounts (×4)              mass_budget: 0.12 kg
    [C-006] Folding hinge system            mass_budget: 0.25 kg
  [SS-02] Propulsion                        mass_budget: 1.4 kg   22.9%
    [C-011] Gasoline engine                 mass_budget: 0.55 kg
    [C-012] Generator                       mass_budget: 0.28 kg
    [C-013] Electric motors (×4)            mass_budget: 0.24 kg
    [C-014] Propellers (×4)                 mass_budget: 0.12 kg
    [C-015] Fuel tank + lines               mass_budget: 0.21 kg
  ...
```

Rules:

- Every C-level component must have: `mass_budget`, `material_hint`,
  `manufacturing_method_hint`.
- Every subsystem must have: `interface_to` (which other SS it connects to, and how).
- Mass budgets must sum to ≤ top-level mass budget. If they don't, flag the
  delta explicitly and ask the user to approve a reallocation before proceeding.
- If a subsystem budget seems physically implausible, flag it with `[RISK]`
  and explain why.

---

## Step 3 — Define Interfaces

For each subsystem-to-subsystem connection, produce an interface record:

```
[IF-001] Airframe ↔ Propulsion
  mechanical:  motor mount bolt pattern, M3×12mm, 4-bolt per mount
  electrical:  ESC power bus, 12V/30A per motor
  thermal:     motor heat → airframe, max 2W conducted per mount
  [RISK] Fold hinge must clear motor rotation arc — verify clearance in assembly skill
```

Flag any interface where you cannot define at least the mechanical connection
type. These are design gaps — list them in an `OPEN INTERFACES` section at the
end.

---

## Step 4 — Generate Build Sequence

Order components by build precedence. Earlier items must be available before
later items can be manufactured or assembled:

```
Build Wave 1 (can start in parallel):
  C-001 Fuselage shell        — carbon fiber layup, 3 days
  C-002 Main wing             — carbon fiber layup, 3 days
  C-011 Gasoline engine       — COTS procurement, 5 days lead
  C-013 Electric motors (×4)  — COTS procurement, 3 days lead

Build Wave 2 (requires Wave 1 complete):
  C-006 Folding hinge         — machined aluminum, depends on wing geometry
  C-004 Landing gear          — depends on fuselage geometry
  ...

Build Wave 3 (integration):
  SS-01+SS-02 Propulsion integration
  IF-001 verification
  ...
```

If you cannot determine the build order for a component, note it as
`[ORDER TBD]` — do not guess.

---

## Step 5 — Vault Write

Write to the Obsidian vault via `authorized_vault_write` (agent: `Librarian`):

**Path:** `projects/{project_name}/requirements.md`
**Frontmatter:**
```yaml
type: system-decomposition
status: draft
confidence: 0.7
tags: [decomposition, requirements, build-plan]
```

**Also write:** `projects/{project_name}/component-tree.md` with the full tree.

**Also write:** `projects/{project_name}/open-questions.md` with all `[RISK]`
and `[ORDER TBD]` items.

---

## Step 6 — Produce Handoff Block

The next skill (`component-generation`) needs to know what to build. End with:

```xml
<decomposition_handoff>
  <project_name>Aladdin-3B</project_name>
  <vault_path>projects/Aladdin-3B</vault_path>
  <components_ready_for_generation>
    <component id="C-001" name="Fuselage shell" mass_budget_kg="0.45"
               material_hint="carbon_fiber_epoxy" method_hint="layup"/>
    <component id="C-002" name="Main wing" mass_budget_kg="0.55"
               material_hint="carbon_fiber_epoxy" method_hint="layup"/>
    ...
  </components_ready_for_generation>
  <build_wave>1</build_wave>
  <open_risks count="N">see projects/Aladdin-3B/open-questions.md</open_risks>
</decomposition_handoff>
```

## Error Recovery

| Problem | Recovery |
|---|---|
| Mass budgets don't sum | Rebalance proportionally, show delta, ask approval |
| Can't determine subsystem for a part | Create SS-XX "Unassigned" bucket, flag for user |
| Requirement has no units | Ask. Never assume. Unitless requirements cause downstream failures |
| User gives conflicting requirements | List the conflict explicitly, propose resolution options |
| >30 components at C-level | Ask user to confirm scope before proceeding — large trees take significant compute |

---

## What This Skill Does NOT Do

- Does **not** generate geometry (that is `component-generation`)
- Does **not** validate requirements against physics (that is `simulation-fea`)
- Does **not** pick specific vendors or part numbers (that is the user's job
  unless explicitly asked)

---

## Completion Criteria

Decomposition is complete when all of the following are true:

- [ ] `system_context` block is filled with no empty fields
- [ ] All mass budgets sum correctly (≤ top-level budget, delta reported if adjusted)
- [ ] Every subsystem has at least one defined interface
- [ ] Build wave sequence is complete with no `[ORDER TBD]` items (or user has approved deferral)
- [ ] Vault notes written and verified:
  - `projects/{project_name}/requirements.md`
  - `projects/{project_name}/component-tree.md`
  - `projects/{project_name}/open-questions.md`
- [ ] Handoff block produced with all Wave-1 components enumerated
