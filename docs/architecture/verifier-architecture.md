# Verifier Architecture

> The FORGE trust boundary: how all outputs are verified before vault persistence.

---

## Principle

No unverified data enters the vault. Every specialist output and every tool result passes through the verification stack. Failure at any mandatory gate rejects the output and raises an error.

---

## Verification Stack (ordered)

### Gate 1: Contract Gate
**Mandatory at MVP**
- Required fields present per `docs/contracts/agent-output-contract.md`
- Type checks (numeric where numeric expected, strings non-empty)
- Version field present and parseable
- Fail action: reject with `ERR_CONTRACT_VIOLATION`

### Gate 2: Unit Gate
**Mandatory at MVP**
- All numeric results have associated units
- Units normalized to SI where applicable
- Mixed-unit detection (e.g., mixing MPa and psi in same expression)
- Internal unit consistency (result units match equation output units)
- Fail action: reject with `ERR_UNIT_MISSING` or `ERR_UNIT_INCONSISTENT`

### Gate 3: Dimensional Gate
**Mandatory at MVP**
- Equation dimensionality checks (LHS dimensions = RHS dimensions)
- Result unit compatibility with declared output type
- Fail action: reject with `ERR_DIMENSIONAL_MISMATCH`

### Gate 4: Provenance Gate
**Mandatory at MVP**
- Source fields present and parseable
- Specificity checks (not just "textbook" — requires author/standard/section)
- Missing or obviously fabricated provenance detected
- Fail action: reject with `ERR_PROVENANCE_MISSING` or `ERR_PROVENANCE_UNSPECIFIC`

### Gate 5: Contradiction Gate
**V1 — deferred from MVP**
- Vault lookup for conflicting claims on same quantity/system
- If conflict found: disputed note created, human review flagged
- Fail action (hard conflict): reject with `ERR_CONTRADICTION_DETECTED`

### Gate 6: Assumption Gate
**V1 — deferred from MVP**
- Hidden assumption scan (LLM-assisted)
- All non-obvious assumptions must be explicitly listed
- Fail action: reject with `ERR_HIDDEN_ASSUMPTION`

### Gate 7: Adversarial Falsification
**V1 — deferred from MVP**
- Failure mode challenges generated by adversarial verifier
- Result must survive challenge or be flagged
- Fail action: flag with `WARN_ADVERSARIAL_CHALLENGE`; escalate if unresolved

### Gate 8: Confidence Calibration
**V1 — deferred from MVP**
- Evidence quality scored
- Claimed confidence vs. evidence quality checked
- Overconfident results downgraded
- Fail action: downgrade confidence; add warning flag

## Red-Team Fixture Pack

Test cases for verifier validation. See `forge-verification/red-team/`.

Categories:
- Wrong units (e.g., force in Joules)
- Dimensional nonsense (e.g., adding stress to temperature)
- Hidden assumptions (e.g., linear material at yield)
- Stale/fake provenance (fabricated citations)
- Contradiction injection (conflicting yield strength values)
- Confidence mismatch (high confidence with weak evidence)
- Simulator-valid / engineering-invalid geometry
